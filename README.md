# VPN Kit — فیلترشکن شخصیِ خودکار با یک دستور

نصب یک **سرور VPN شخصی** روی هر سرور اوبونتوی خارج از ایران، با **VLESS + Reality**، پنل مدیریت کاربر، لینک اشتراک خودکار، ربات تلگرام، نگهبان ضدفیلتر، پشتیبان رمزگذاری‌شده و **مهاجرت خودکار به سرور جدید**. همهٔ این‌ها فقط با یک دستور.

```bash
bash <(curl -Ls https://raw.githubusercontent.com/OWNER/REPO/main/install.sh)
```

> `OWNER/REPO` را با نام‌کاربری و نام مخزن خودت عوض کن (راهنمای بخش «[گذاشتن روی گیت‌هاب](#گذاشتن-روی-گیتهاب)»).

## این پروژه چه می‌کند؟

| بخش | کار |
|---|---|
| **3x-ui** (نسخهٔ سنجاق‌شده) | پنل مدیریت و هستهٔ Xray |
| **دو کانفیگ Reality** | پورت ۴۴۳ با TCP و پورت ۸۴۴۳ با XHTTP؛ هر کدام با سایت استتار جدا |
| **لینک اشتراک** | یک آدرس که همهٔ کانفیگ‌های هر کاربر را می‌دهد و در برنامه هر ساعت خودکار به‌روز می‌شود |
| **TLS معتبر** | گواهی Let's Encrypt با DNS-01 از راه کلادفلر، با تمدید خودکار |
| **API دستیار** | مدیریت کاربر، وضعیت سرور، مقصدها، DNS و مهاجرت؛ از پشت کلادفلر، پس حتی اگر آی‌پی در ایران بسته شود در دسترس است |
| **نگهبان (Watchdog)** | هر ۳ دقیقه سلامت سایت‌های استتار را می‌سنجد و اگر یکی خراب شد، خودش عوضش می‌کند |
| **ربات تلگرام** | وضعیت، بررسی فوری، آدرس اشتراک، راه‌اندازی مجدد، هشدار |
| **بستهٔ مهاجرت** | هر شب یک فایل رمزگذاری‌شده با همهٔ سیستم؛ با یک دستور روی سرور جدید بالا می‌آید |

### چرا این طراحی؟

- **Reality** به سرور اجازه می‌دهد خود را جای یک سایت واقعی (مثلاً مایکروسافت) جا بزند؛ بدون گواهی جعلی و بدون دامنهٔ پشت‌پردهٔ قابل‌شناسایی.
- **کانفیگ‌ها مستقیم هستند، نه پشت کلادفلر.** در آزمایش‌ها، کانفیگ‌های پشت پروکسی کلادفلر (WebSocket و XHTTP) و پروتکل‌های UDP مثل Hysteria2 روی اینترنت موبایل ایران جواب ندادند. فقط **آدرس اشتراک و API** پشت کلادفلر هستند تا همیشه باز شوند.
- **آدرس کانفیگ‌ها دامنه است، نه آی‌پی.** وقتی آی‌پی سرور بسته شد، فقط رکورد DNS عوض می‌شود و لینک کاربرها دست نمی‌خورد.

## پیش‌نیازها

1. **یک سرور** خارج از ایران:
   - اوبونتو ۲۲٫۰۴ یا ۲۴٫۰۴ (دبیان ۱۲ هم باید کار کند)، **حداقل ۱ گیگ رم**، دسترسی `root`
   - ترجیحاً آی‌پی تمیز؛ هر کس که آی‌پی را بخرد ممکن است آن را قبلاً فیلتر شده بگیرد (بخش [آنچه تست شده](#آنچه-تست-شده-و-محدودیتها))
2. **یک دامنه** که در **کلادفلر** (حساب رایگان کافی است) اضافه شده باشد.
3. **توکن API کلادفلر** (بخش بعد).
4. (اختیاری) **توکن ربات تلگرام** از `@BotFather`.

## ساخت توکن کلادفلر (قدم‌به‌قدم)

1. وارد [داشبورد کلادفلر](https://dash.cloudflare.com/profile/api-tokens) شو ← **My Profile ← API Tokens ← Create Token**.
2. قالب **Edit zone DNS** را انتخاب کن.
3. در **Zone Resources**: دامنهٔ خودت (یا «All zones»).
4. **Continue to summary ← Create Token** و توکن را کپی کن. **فقط یک بار نشان داده می‌شود.**

> این توکن فقط برای ساخت رکورد DNS و گواهی TLS است. روی سرور نگه داشته می‌شود (برای تمدید گواهی و تغییر DNS هنگام مهاجرت) و در پوشه‌ای با دسترسی فقط-root.

## نصب

روی سرور تازه، با کاربر root:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/OWNER/REPO/main/install.sh)
```

نصب‌کننده این‌ها را می‌پرسد:

| سؤال | مثال |
|---|---|
| دامنهٔ مستقیم برای کانفیگ‌ها | `cdn.example.com` |
| دامنهٔ اشتراک (پشت کلادفلر) | `sub.example.com` |
| توکن کلادفلر | `…` |
| توکن ربات تلگرام (اختیاری) | `123456:ABC…` |

یا همه را یک‌جا بده (بدون پرسش):

```bash
bash <(curl -Ls https://raw.githubusercontent.com/OWNER/REPO/main/install.sh) \
  --domain cdn.example.com --sub-domain sub.example.com \
  --cf-token XXXXXXXX --tg-token 123456:ABC --client admin
```

گزینه‌های دیگر:

| گزینه | معنی |
|---|---|
| `--client NAME` | نام اولین کاربر (پیش‌فرض `admin`) |
| `--ip-only` | بدون دامنه؛ فقط کانفیگ‌های Reality روی آی‌پی (بدون اشتراک، TLS و دستیار) |
| `--no-assistant` | بدون API، ربات، نگهبان و پشتیبان |
| `--force-new` | دیتابیس 3x-ui موجود را پاک و از صفر شروع کن (**داده‌ها از بین می‌روند**) |

حدود **۲ تا ۵ دقیقه** طول می‌کشد. کارهایی که می‌کند: نصب 3x-ui، ساخت رکوردهای DNS، گرفتن گواهی، ساخت دو اینباند Reality با کلیدهای تازه و دو سایت استتار سالم، ساخت اولین کاربر، نصب دستیار و ساخت اولین بستهٔ مهاجرت.

در پایان همه‌چیز (آدرس پنل، رمز، لینک اشتراک، توکن API، رمز بسته) چاپ و در `/root/vpn-kit-info.txt` ذخیره می‌شود (فقط root می‌خواند). **همان لحظه یک کپی از رمز بسته و اطلاعات پنل را جای امن بیرون از سرور نگه دار.**

## بعد از نصب: وصل شدن

**آدرس اشتراک** را در یکی از این برنامه‌ها اضافه کن:

| پلتفرم | برنامه |
|---|---|
| اندروید | Hiddify، v2rayNG (نسخهٔ جدید برای XHTTP) |
| iOS | Streisand، Hiddify، V2Box |
| ویندوز | v2rayN، Hiddify |
| مک | Hiddify، V2Box |

**تنظیمات پیشنهادی در برنامه** (برای اینستاگرام و تلگرام روان‌تر):
- **Block QUIC** روشن
- **MTU** بین ۱۳۰۰ تا ۱۴۰۰

> هر دو کانفیگ (۴۴۳ و ۸۴۴۳) در اشتراک هست. اگر یکی کند بود دیگری را امتحان کن؛ بسته به اپراتور فرق می‌کند.

## اتصال برنامهٔ اندروید

در پایان نصب این‌ها چاپ می‌شود:

- **Android token** (توکن اندروید)
- **Connection string** (رشتهٔ اتصال) به شکل `vpnkit://connect?api=…&token=…&name=…`
- یک **QR** از همان رشته (داخل ترمینال)

در برنامه: «سرورهای من» ← **اسکن QR** (یا «چسباندن» رشته). برنامه با توکن به `https://SUB_DOMAIN:2053/v1/info` وصل می‌شود، نام سرور و لینک اشتراک را می‌گیرد، اشتراک را خودکار اضافه می‌کند و از آن به بعد کاربرها، وضعیت سرور، مقصدها، DNS و مهاجرت را مدیریت می‌کنی. چند سرور را می‌شود کنار هم نگه داشت. اگر رشته را در یک پیام یا یادداشت گذاشتی، مثل رمز با آن رفتار کن: هر کس آن را دارد کنترل سرور را دارد.

برنامه به API **دستیار** وصل می‌شود، نه مستقیم به پنل 3x-ui؛ پنل لازم نیست از اینترنت قابل‌دسترس بماند.

> **نکتهٔ کلادفلر در ایران:** بعضی آدرس‌های لبهٔ کلادفلر (مثل `188.114.96.11`) از ایران timeout می‌دهند و بعضی (مثل `188.114.96.7`) کار می‌کنند. در آزمایش‌ها، برنامه با امتحان کردن آدرس بعدی مشکلی نداشت؛ اگر یک بار اتصال نشد، چند ثانیه بعد دوباره امتحان کن.

## مدیریت کاربران

### پنل 3x-ui
آدرس و رمز را از `/root/vpn-kit-info.txt` بردار. هر کاربر را با **Add Client** بساز و هر دو اینباند را برایش انتخاب کن تا اشتراکش هر دو کانفیگ را بدهد.

### API دستیار
همهٔ درخواست‌ها هدر `X-Token` (توکن API) می‌خواهند و آدرسشان `https://SUB_DOMAIN:2053` است.

```bash
TOKEN=...; API=https://sub.example.com:2053

# فهرست کاربران با مصرف و وضعیت
curl -s -H "X-Token: $TOKEN" $API/v1/users

# ساخت کاربر: ۵۰ گیگ، ۳۰ روز
curl -s -H "X-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"ali","gb":50,"days":30}' $API/v1/users/create

# تمدید ۳۰ روز، افزودن ۱۰ گیگ
curl -s -H "X-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"email":"ali","addDays":30,"addGb":10}' $API/v1/users/update

# غیرفعال‌کردن / حذف
curl -s -H "X-Token: $TOKEN" -H "Content-Type: application/json" -d '{"email":"ali","enable":false}' $API/v1/users/update
curl -s -H "X-Token: $TOKEN" -H "Content-Type: application/json" -d '{"email":"ali"}' $API/v1/users/delete
```

فهرست کامل در [docs/api.md](docs/api.md).

## ربات تلگرام

۱. از `@BotFather` یک ربات بساز (`/newbot`) و توکن را موقع نصب بده.
۲. در پایان نصب یک دستور مثل `/start abc123` چاپ می‌شود. آن را برای رباتت بفرست؛ از این لحظه ربات **فقط به تو** جواب می‌دهد (کد یک‌بارمصرف است).
۳. دکمه‌های منو: **وضعیت، بررسی همین حالا، رویدادها، آدرس اشتراک، راه‌اندازی مجدد، راهنما**.

> تلگرام در ایران بدون فیلترشکن باز نمی‌شود. هشدارهای ربات بعد از رویداد می‌رسند؛ خودِ نگهبان قبل از آن مشکل را رفع می‌کند.

## خودکارسازی

- **نگهبان:** هر ۳ دقیقه سایت‌های استتار هر اینباند را می‌سنجد (باید با TLS 1.3 و h2 جواب بدهند). اگر دو بار پشت‌سرهم خراب بود، به نفر بعدیِ سالم فهرست عوض می‌کند، از دیتابیس پشتیبان می‌گیرد و 3x-ui را راه‌اندازی مجدد می‌کند. همچنین اگر x-ui خاموش شد دوباره راهش می‌اندازد.
- **هشدارها** (هر ۵ دقیقه): مصرف کاربر به ۹۰٪ یا ۱۰۰٪ رسید، انقضای کمتر از ۳ روز، رم بالای ۹۰٪، دیسک بالای ۸۵٪، گواهی کمتر از ۱۰ روز، x-ui خاموش.
- **اشتراک:** فاصلهٔ به‌روزرسانی ۱ ساعت است؛ تغییر مقصد در یک ساعت به کاربرها می‌رسد.

## مهاجرت به سرور جدید

### بسته چیست؟
هر شب (و هر وقت بخواهی) یک فایل `hamid-bundle-*.tgz.enc` ساخته می‌شود (AES-256، رمز در `/etc/hamid-backup.key`) که داخلش هست: دیتابیس 3x-ui (کاربران، کلیدها)، گواهی TLS، توکن کلادفلر، تنظیمات، کد دستیار و نصب‌کنندهٔ `restore.sh`. حجمش حدود ۵۰ کیلوبایت است. هفت بستهٔ آخر روی سرور می‌ماند و اگر ربات تلگرام وصل باشد، نسخه‌ای هم همان‌جا ذخیره می‌شود.

> **رمز بسته را بیرون از سرور نگه دار.** بدون آن بسته باز نمی‌شود، و با آن هر کس بسته را داشته باشد همه‌چیز را دارد.

### حالت ۱ — سرور قدیمی هنوز زنده است (آی‌پی فیلتر شده)
از API: سرور جدید را با آی‌پی و رمز root آماده کن، بعد فعال کن:

```bash
curl -s -H "X-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"host":"NEW_IP","password":"ROOT_PASSWORD"}' $API/v1/spare/start     # آماده‌سازی (آماده‌باش)
curl -s -H "X-Token: $TOKEN" $API/v1/spare                                   # پیگیری گزارش
curl -s -X POST -H "X-Token: $TOKEN" -H "Content-Type: application/json" -d '{}' $API/v1/spare/promote   # جابه‌جایی: DNS عوض می‌شود
```

تا وقتی `promote` را نزنی هیچ چیز فعلی تغییر نمی‌کند.

### حالت ۲ — سرور قدیمی از بین رفته
۱. بستهٔ تلگرام (یا فایل ذخیره‌شده) را روی سرور جدید ببر؛ نامش را `hamid-bundle.tgz.enc` بگذار.
۲. این را اجرا کن (رمز بسته را جای `KEY` بگذار):

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -pass pass:'KEY' -in hamid-bundle.tgz.enc | tar xz -C /root \
  && bash /root/hamid-bundle/restore.sh
```

`restore.sh` همه‌چیز را نصب می‌کند، سرویس‌ها را روشن می‌کند و **رکوردهای DNS را خودکار روی آی‌پی جدید می‌گذارد.** لینک کاربرها و برنامه‌ها همان می‌ماند، چون به دامنه وصل‌اند. با `--standby` فقط نصب می‌شود و DNS تغییر نمی‌کند.

## عیب‌یابی

| نشانه | علت محتمل و راه‌حل |
|---|---|
| همهٔ کانفیگ‌ها یک‌دفعه جواب نمی‌دهند، ولی پورت‌ها باز است | سایت استتار از روی سرور باز نمی‌شود. `python3 /usr/local/bin/reality-watchdog.py --rotate` یا از ربات «بررسی همین حالا» |
| فقط از ایران وصل نمی‌شود (از بیرون کار می‌کند) | آی‌پی یا کل رنج آن فیلتر است. سرور جدید در شبکهٔ دیگر بگیر و مهاجرت کن. بررسی سریع: از گوشی با اینترنت ایران `ping` و اتصال TLS به آی‌پی |
| `x-ui` بعد از مهاجرت بالا نمی‌آید | `journalctl -u x-ui -n 30`. اگر نوشت `database disk image is malformed` یعنی فایل‌های `*-wal` قدیمی مانده؛ نسخهٔ فعلی `restore.sh` خودش پاکشان می‌کند |
| گواهی صادر نشد | توکن کلادفلر دسترسی **Zone:DNS:Edit** را ندارد یا دامنه در همان حساب نیست |
| اشتراک ۴۰۴ می‌دهد | `sqlite3 /etc/x-ui/x-ui.db "select * from settings where key='subPath'"`؛ باید فقط یک ردیف باشد |
| خطا در API: `ارتباط با سرور برقرار نشد` | دامنهٔ اشتراک باید «Proxied» (ابر نارنجی) و پورت ۲۰۵۳ باز باشد |

لاگ‌ها: `journalctl -u hamid-api`، `journalctl -u x-ui`، `/var/log/reality-watchdog.log`.

## امنیت

- توکن‌ها و رمزها فقط در فایل‌هایی با دسترسی `600` می‌مانند (`/etc/hamid-api.env`، `/etc/reality-watchdog.env`، `/etc/vpnkit/`، `/root/vpn-kit-info.txt`).
- **توکن API کنترل کامل کاربرها را می‌دهد.** آن را در پیام‌رسان یا گیت نگذار.
- پورت پنل تصادفی و مسیر پنل تصادفی است، ولی روی اینترنت باز است. اگر می‌خواهی ببندی: `ufw delete allow PORT/tcp` و با تونل SSH وارد شو.
- پیشنهاد: رمز root را بعد از نصب عوض کن و ورود با کلید SSH را فعال کن.

## آنچه تست شده و محدودیت‌ها

**تست‌شده (روی سرور واقعی، اوبونتو ۲۴٫۰۴):**
- نصب از صفر با یک دستور، با دامنه و کلادفلر: گواهی، DNS، دو اینباند، کاربر اول، اشتراک (دو لینک) و API از پشت کلادفلر. هر دو کانفیگ ساخته‌شده از اشتراک به اینترنت وصل شدند.
- ساخت بستهٔ مهاجرت، رمزگشایی، و نصب روی سرور دیگر در حالت آماده‌باش.
- مدیریت کاربر (ساخت، تمدید، ریست، غیرفعال، حذف) از راه API.

**تست‌نشده یا محدودیت:**
- `promote` (جابه‌جایی DNS با مهاجرت زنده) و حالت ۲ (بازیابی از بستهٔ تلگرام روی سرور خالی) در شرایط کامل یک جابه‌جایی واقعی آزموده نشده‌اند.
- حالت `--ip-only` فقط ساختار را می‌سازد و کم‌تر آزموده شده.
- **هیچ نصب‌کننده‌ای نمی‌تواند تضمین کند آی‌پی سرور فیلتر نشده باشد.** در یکی از آزمایش‌ها، آی‌پی یک سرور تازه در آمستردام با وجود کارکرد کامل از بیرون، از ایران قابل‌استفاده نبود (اتصال TCP برقرار می‌شد ولی TLS گیر می‌کرد). قبل از معرفی سرور به کاربران، با اینترنت ایران تستش کن.
- نسخهٔ 3x-ui روی `v3.11.0` سنجاق شده؛ نسخه‌های جدیدتر ممکن است ساختار دیتابیس یا API را عوض کنند.
- برنامهٔ اندروید «دستیار حمید» جداست و در این مخزن نیست.
